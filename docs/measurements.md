# Measurements

What alpheus costs in memory and wake-ups, how it is measured, and how it
compares with other shells. Updated with every delivery that costs anything
(see [CONTRIBUTING](../CONTRIBUTING.md#documentation)).

## Method

- **Release builds only.** The budget tests refuse a debug build: it inflates
  PSS by roughly 2x (measured 2026-10-05: startup with every module 17.4 MB
  in debug against 7.8 MB in release), which would either fail a budget tuned
  for release or pass one loosened to fit debug (header of
  `crates/alpheus-daemon/tests/memory.rs`).
- **Back to back against a base commit.** A delivery is measured against the
  commit just before it, usually three runs each (a row says when it was not), each build in its own target
  directory, on the same machine in the same sitting.
- **Trust the deltas, not the absolutes.** PSS drifts by about ±0.5–1 MB
  between boots (shared libraries are counted proportionally, the page cache
  moves), so a figure is compared with the base's figure from the same
  session, never with an older absolute.
- **Leak bounds are on anonymous memory.** The tests that bound growth over
  cycles read `Anonymous:` (heap, thread arenas, stacks, written data) from
  `smaps_rollup`, and print total PSS and the shm pools instead of asserting
  them: file-backed pages (code, fonts) and the compositor's mapping of the
  pools move by ±200 KB or more with whatever else ran before.
- **PSS, not RSS.** `/proc/<pid>/smaps_rollup`, which splits shared pages
  between the processes that map them.
- **Wake-ups are counted on the event loop at rest.** A test lets the
  daemon idle for a window (typically 5 s) after the scenario it checks and
  counts the loop's wake-ups; the target is zero, apart from planned timers
  (the clock's minute tick, the resources interval). Tests also count the
  D-Bus and sound threads' wake-ups and the whole daemon's.
- **Startup budget.** PSS at start must stay under 15 MB (firm), and the
  steady state under 15 MB too (the resident budget of
  [`decisions.md`](decisions.md#everything-alpheus-keeps-resident-fits-in-15-mb-at-rest)), without growth, under a busy compositor and a busy
  PipeWire (`STARTUP_MAX_KB` and the header of `tests/memory.rs`).
- **No session involved.** The tests run a headless Sway with virtual
  outputs, a private D-Bus daemon replaying recorded NetworkManager, UPower
  and BlueZ replies, and a script standing in for `pw-dump`; nothing touches
  a real session.
- **Where the figures come from.** alpheus's own rows are release builds
  measured by `tests/memory.rs` on a headless Sway, as described above. Only
  the rows marked live, and the other shells' rows, were read on a real
  session (one laptop, Hyprland, three outputs). Each row names the test that
  produced it; most pages under `docs/features/` give the base commit and the
  run count of their delivery's measurement, and the rest are in the
  project's history.

## How to run

```sh
cargo test -q --release -p alpheus-daemon --test memory -- --include-ignored --test-threads=1
```

`--include-ignored` runs the budget tests, which are marked `#[ignore]` so
that a plain `cargo test` skips them, together with the few ordinary tests of
the file; the header of `tests/memory.rs` gives the same command with
`--ignored`, which runs the budget tests alone.

On the Nix setup, prefix it with `nix develop -c`. The tests need a headless
Sway, a `dbus-daemon` and the other tools of the dev shell; they never run
against the live session.

## Memory

How much RAM a desktop shell keeps resident, measured as PSS
(`/proc/<pid>/smaps_rollup`). [Method](#method) says which figures come from
the tests and which from a real session. Updated with every delivery.

### Parts that are not resident

Every change measures every part it touches (decisions.md, "Every part is measured, resident or
not"). The control center and `alpheus-launch` run on demand and exit; their memory is read by two
release-only tests, each in its own isolated environment (cleared environment, temporary XDG
directories, no session tool, no session bus):

```sh
nix develop -c cargo test -q --release -p alpheus --test memory -- --include-ignored --test-threads=1
nix develop -c cargo test -q --release -p alpheus-daemon --test launch_memory -- --include-ignored --test-threads=1
```

First figures, 2026-11-27, release, three runs each on the base of the feature batch (07227887),
while other worktrees' headless suites ran on the same machine:

and peak 11 MB for the control center (its PSS read 3.6 MB once, in an earlier run of the same

state, tool or bus is touched. The test also asserts that every call the tabs made was one a
fake answers, so a changed argv cannot measure error screens.
